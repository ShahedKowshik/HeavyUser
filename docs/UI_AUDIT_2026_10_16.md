# HeavyUser — Comprehensive UI / accessibility source audit
**Audit date:** 2026-10-16
**Target:** current desktop, tablet and mobile web code on main
**Design reference:** https://ui.shadcn.com/create?preset=buFywKm (Lyra, Inter, neutral, compact, square corners)

## Approach and evidence
Inspected every active user-facing React surface and six layered stylesheets:
- `src/app/page.tsx` — Today, All, Archive, login, habits, logging, statistics, history, modals and mobile navigation.
- `src/app/habit-views.tsx` — Week table and month calendar.
- `src/app/account-settings.tsx` — profile, email/password, data, dialogs.
- `src/app/design-system.css`, `compact.css`, `tracker-enhancements.css`, `habit-experience.css`, `ux-consistency.css`, `account.css`.
- Checked project design instructions, responsive breakpoints, actual markup for labels/ARIA/roles, focus behavior, fixed-position navigation, empty states and date navigation.

Reference standards:
- WCAG 2.2, https://www.w3.org/TR/WCAG22/
- Understanding WCAG 2.2: https://www.w3.org/WAI/WCAG22/understanding/
- NN/g Web Form Design: https://www.nngroup.com/articles/web-form-design/
- W3C SC 2.5.8 *Target Size (Minimum)* is **24×24 CSS px or qualifying spacing/exceptions**; this project uses **~44px for important mobile actions** as a usability target, not as a false AA requirement.
- Normal-sized text target 4.5:1; interface components and graphical objects generally require 3:1 where essential.
- Avoid implying automated tests prove full WCAG conformance.

## Verified code findings and fixes

### Critical and high priority
| # | Area | Source-observed issue | Resolution |
|---|---|---|---|
| 01 | Week grid | A clickable `button` was assigned `role=rowheader`, replacing its native role | Wrap the button in a real `role=rowheader` element |
| 02 | Week navigation | Horizontal scroll region lacked keyboard focus | Named, keyboard-focusable scroll region |
| 03 | Week on phones | A 660px table lacked a visible horizontal-swipe instruction | Short swipe hint only on phone layouts |
| 04 | Week interaction | Check-off actions were not announced as toggles | `aria-pressed` plus action-specific names |
| 05 | Week dates | Today's column only used visual highlight | `aria-current=date` on today's heading |
| 06 | Month calendar | Today and selected date distinguished only visually | `aria-current=date` / `aria-pressed` |
| 07 | Month calendar | Accessible date labels omitted year and full weekday | Full date and outcome in button label |
| 08 | Month weekdays | Single-letter day headers were ambiguous with duplicate letters | Full weekday accessible names |
| 09 | Account dialog | Keyboard focus initially stayed behind the overlay | Move focus into settings when opened; restore focus to launcher when closed |
| 10 | Navigation | Desktop and mobile active states used CSS only | Set `aria-current=page` on current view |
| 11 | Repeat picker | Day selections only had a styling class | Full weekday names and `aria-pressed` state |
| 12 | Historical navigation | Smooth scrolling ignored reduced-motion preference | Honor `prefers-reduced-motion` |
| 13 | Chart | Screen reader only heard 'Last N days progress' without a data location | Reference accessible recent-history values in chart label |

### Type, contrast and hierarchy
| # | Area | Source-observed issue | Resolution |
|---|---|---|---|
| 14 | List | Multiple secondary labels used 10px desktop | Readable 12px supporting text |
| 15 | Statistics | Metric descriptions shrank to 10–11px | 12px/1.45 minimum supporting type |
| 16 | History | Dates and statuses were 9–11px at narrow sizes | 12px, readable line height, wrapping |
| 17 | Chart | Legend and date labels were 9–10px in phone layouts | 11–12px and clearer spacing |
| 18 | Status | Some details caption types were too small | Consistent supporting type and contrast |
| 19 | Account | Old labels and helper text remained 11px | Normalized 12–13px and readable helper line-height |
| 20 | Forms | Habit inputs inherited small text on mobile, risking iOS focus zoom | 16px input text on mobile |
| 21 | Account forms | Account text inputs also risked automatic iOS zoom | 16px mobile inputs |
| 22 | Charts | Partial-progress gray bar was #a3a3a3 (<3:1 against white) | Darker #858585 bar; visible missing-state outline |
| 23 | Muted text | Different modules defined multiple inconsistent gray colors | Standard accessible neutral #626262 for supporting text |
| 24 | Button focus | Region and button focus treatments differed | Strong consistent high-contrast 2px focus indicators |
| 25 | Data display | Digit widths could vary and make column comparison difficult | Tabular numeric figures in counts and statistics |

## Implemented code changes
- `src/app/ui-audit.css`: final layer of spacing, typography, color contrast, hit areas, small-phone responsive rules.
- `src/app/habit-views.tsx`: week table semantics, scrolling hints, labels, date states, no-habit state.
- `src/app/page.tsx`: keyboard names, nav state, form weekdays, chart labels, reduced motion, CSS integration.
- `src/app/account-settings.tsx`: keyboard focus enter/restore.
- `tests/ui-accessibility-audit.test.mjs`: verifies regressions and calculated color contrast.

## Explicitly not claimed
- This is a **comprehensive source-code UI audit**, not a visual pixel-by-pixel comparison of authenticated browser screenshots. The active app requires user sign-in; no private browsing session or signed-in Mac/phone viewport was available.
- No automated axe, Lighthouse, screen-reader session or real-device pinch-zoom measurements were run. WCAG conformance must not be asserted from static code checks.
- Existing app behavior, habit statistics, Supabase schema and user records were not changed.
- Keeping the square-corner compact Lyra aesthetic is intentional, even though other products choose larger type/card spacing.
- Remaining follow-up for a fully visual QA sign-off: test at 320/360/390/430/768/1024/1440px, 200% browser zoom; Mac keyboard only; Android Chrome; iOS Safari; TalkBack/VoiceOver; long translated habit names; 30-day charts; empty states; login and email reset; account modal after avatar upload.
